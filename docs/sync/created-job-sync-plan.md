# Exchange offline-created company Jobs

Plan for root review only. Governing [issue #61](https://github.com/xXKillerNoobYT/Weird-Parts-3rd-run/issues/61#issuecomment-6232961115), under #33. Base `6a0022e134e332d9b108850079ca6022698e39d8`, branch `codex/issue61-created-job-sync`. No implementation or SDK validation is authorized by this document.

## Outcome and boundaries

Two already enrolled, mutually retained same-company installations each create a distinct Job offline through `CompanyJobCommands.createJob`. After Pair, Match, retained-peer authentication, and visible manual sync availability on the responder, one explicit **Sync Now** drives both directions. Both production `listJobs` calls return the two original Job projections and IDs. Separately verify that stored operations/audits retain original authors, signatures, and exact operation bytes. Repeat and cold restart retain one record per operation and Job. Interrupted transfer remains pending for a fresh Sync Now.

This slice exchanges `job.create@1` only. It introduces no unknown peers, whole-shop copy, re-authored remote commands, edits, deletion, photos, settings, users, Bluetooth, background work, or mesh. Existing `localContinuity` and capability restrictions apply. Existing authority packages do not gain rights or Job history.

## Source facts and decisions

- `create_job.dart` already parses canonical operations and verifies owner authorization v2 or member authorization v3 against current receiver facts and floors. It has no incoming admission API. Its `validateCreateJobCommit` requires `outgoing=true` and receipt receiver equal to operation origin. Preserve that validator and old receipt/signature bytes.
- `company_jobs` already has immutable operation bytes, projection, audit, local receipt, origin/request uniqueness, and an `outgoing` flag. Store an admitted remote operation there with `outgoing=false`; outgoing means local preparation, never peer delivery.
- `CompanyPeerAuthentication` supplies an opaque retained-peer capability. Match and membership alone grant no business access. Both disclosure and admission enforce the current effective company/shop/createJob/list permission path. Holdings include all validated scoped records; eligible payload offers include only records authored by the sending installation. Admission requires the authenticated peer to be that original author. Relay remains outside this slice.
- `NearbyController.sendJoinMessage` owns outbound request order. Reuse its dispatcher and queue. Never route sync through `sendTo`, `BackupPayload`, or a second network service.

## Incoming admission and recovery

Add `CompanyJobCommands.applyIncomingCreate` and an opaque verified incoming operation in `create_job_sync.dart`. Require a live local `OwnerSession`, current `VerifiedPeerMembership`, manual sync availability, and effective company/shop/createJob/list permissions. Verify exact canonical bytes, assertion/body attribution, signature, facts, capabilities, floors, and author device equal to the authenticated peer. The kernel verifies its retained installation/generation/key binding. Never re-author the operation.

Own a top-level SQLite transaction and take the existing installation-binding write lock. Repeat current authorization and peer verification before protected admission. Check both operation identity `(company, originGeneration, requestId)` and Job ID. An exact existing operation must also match full canonical bytes, command, projection, audit, and receiver receipt seal; return its saved receipt without mutation. Any conflicting request, author, bytes, or occupied Job ID refuses without a success ACK. Apply the existing 512-Job shop limit before a new intent, with exact retries permitted at capacity.

Add explicit `jobCreateIncoming` intent encoding `job.create.incoming@1`, a separate incoming receipt admission class/domain `wiredpart.job.create.incoming.receipt@1:`, and `validateIncomingCreateJobCommit`. Keep incoming receipt decoding separate from the old v2 decoder. Its compact, strictly keyed v1 payload binds company/shop, Job ID, origin generation/request, operation and command commitments, SHA-256 of the complete canonical operation, receiver installation/generation, and receiving-store generation. Its key binds origin/request to this receiver/store. The validator requires `outgoing=false`, exact original user/device audit, and the exact signed initial projection. The new receipt cannot satisfy a local-create intent.

Extend installation receipt lookup, witness, validation, and seal dispatch explicitly for this family. The incoming witness covers the Job and company-job record. Do not change old family witness encodings. Use existing begin CAS, receipt seal, after-witness CAS, post-hook `validateHeldCompanyCommand`, SQL commit, and completion reconciliation. Lost CAS replies or process interruption use the existing before/after witness rules. Divergence fails closed, without repair or re-signing. `listJobs` dispatches local records to the unchanged old verification and incoming records to the new verifier.

`requireCurrent()` calls `readCompanyTrust -> reconcile`, which cannot run with a pending intent inside the transaction. Add an opaque held-context check tied to the exact intent, protected revision, pinned trust/floors/custody, live owner/channel, and retained peer. Reuse low-level membership verification without recursive reconciliation; expose no `skipReconcile` switch. Recheck after signing and at the last actual await before commit, then synchronously check owner/channel validity. Normal full `requireCurrent()` applies before admission/disclosure and after completion. Sign-out, background, expiry, stop, replacement, or authority change cancels remaining work.

## Changes-only exchange and acknowledgments

Add one company sync coordinator, `company_created_job_sync.dart`, inside the installation-security library. It owns a small explicit phase state machine and the authenticated peer; UI passes neither signing bytes nor keys. Derive separate directional sync AEAD keys from the actual live channel with HKDF label `wiredpart-v2/company-job-create-sync@1/{direction}`. Reuse existing bounded envelope checks, request sequence owner, session/direction/recipient binding, random nonce checks, five-minute lease, and shared 128-received-nonce budget. Preserve Join and legacy-copy formats.

After mutual proof and responder availability, the initiator sends `company.job.create.sync@1` start. Both sides enforce effective permissions and freeze a sorted HOLDINGS inventory of all validated scoped records, including received rows. Strict descriptors bind operation identity, Job ID, original author, body commitment, complete-byte digest, and length. Bound each descriptor to 1 KiB, each page to 32 descriptors plus at most 1 KiB framing, and each inventory to 512 descriptors, 16 pages, and 528 KiB of canonical page bytes in aggregate. Thus a page is at most 33 KiB, below the 40 KiB plaintext limit. Measure exact worst-case encoding; never truncate. Reject duplicate/conflicting pages, identities, excess aggregate bytes, or inconsistent ordinal/count/inventory digest before transfer.

OFFER eligibility is separate from holdings. Transfer only sender-authored payloads missing from the receiver. Received rows advertise presence and can supply exact receiver ACKs, preventing unnecessary resend of own-origin operations on repeat sync. Missing records authored by another installation remain unsupported pending work, without silent relay or a claim of global convergence. A Job created after the frozen snapshot remains pending for the next run.

The initiator drives an alternating send/request schedule so both directions get service. Send only descriptors absent at the receiver. Pack byte-bounded chunks; one operation reassembles in memory at a time, at most 65,536 bytes. Use at most 24 KiB raw per chunk, leaving room for base64 and headers inside the existing 40 KiB plaintext and 64 KiB HTTP limits. Bind transfer/request ID, exact descriptor, offsets, total size, and digest. Reject gaps, overlap, changed identity, excess length, or digest mismatch before admission. No partial operation reaches SQL.

After admission AND reconciliation, return a typed installation-signed `company.job.create.ack@1` binding the descriptor, receiver installation/generation/store, and saved receipt digest. Its typed kernel signer validates the saved local or incoming receipt and exact row; expose no generic sign-bytes API. The proposed compact receipt/ACK cap is 4 KiB; measure maximum admitted identity fields before finalizing it. Recheck membership, effective permissions, and availability before/after signing and transmission. Add a typed disclosure guard inside the outbound queue and after socket-open, immediately before the first body bytes. The sender verifies retained key and scope/descriptor before persistence. HTTP `ok` or inventory presence is never delivery proof. A matching inventory with missing ACK requests that ACK without resending the operation. Rejection sends no success ACK and retains the source.

Use additive schema **8** for one `company_job_peer_acks` table, keyed by company/origin/request and retained peer device. Store its exact installation/generation/store binding, operation digest, and signed ACK. Keep one latest verified statement per operation/retained peer, bounded by 512 Jobs times 128 retained peers per shop; unknown bindings refuse. Exact ACK retry is a no-op. Changed store evidence replaces only after fresh authenticated verification. Check signatures on read. ACKs are delivery evidence, never authority/floors. Every fresh run still uses current inventory. Restart restores neither ephemeral keys nor in-flight success; lost ACKs come from saved receiver records.

The unchanged pair owns the aggregate 128 received-nonce slots and five-minute lease across original Join/proof and every derived sync codec/attempt. Expose its actual remaining slots/lease; exchange authenticated remaining-budget snapshots and debit all subsequent envelopes. A new codec or Sync Now never resets either limit. The 112 sync-envelope count is only a ceiling. Calculate each directional budget from actual remaining receive slots, reserve control/completion and current-operation reply capacity before enqueueing, and stop before either endpoint exhausts its quota or lease. Preconsumed channels can have much less capacity. Report confirmed counts plus **More Jobs pending. Pair again and retry Sync Now.** No automatic re-pair. Success covers only the supported frozen scope, with both directions confirmed and no unsupported pending records; interruption/refusal cannot report success.
