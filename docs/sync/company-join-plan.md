# Authorized nearby Join — first complete increment

Plan for #60 under #33, based on `b92e6124e1521310644da16f682b4e1525dff9f3` (#99, PR100 still unmerged). One builder owns this branch. Root owns contract/security review, GitHub and native acceptance; no product implementation or SDK work before this plan's review.

## Outcome and boundary

Windows A retains its existing company, Job and immutable history. A signed-in user with current user **and** device `enrollDevice` permission explicitly approves fresh Mac B. B proves its installation key, receives a constrained grant for the **same existing company user and PIN**, activates rootless member custody, normally quits/restarts locked, then signs in with that PIN. A/B prove membership again over a fresh connection without the original pairing session. B starts with no Jobs; if effective permission includes `createJob`, one local Job must work through the existing production command and receipt path.

B gets no `enrollDevice`; A can approve C using the same protocol. A third independent identity is required in protocol tests, not actual three-device relay acceptance. Business catch-up/sync belongs to #61. Excluded: business copy/backup, authority recovery as Join, user creation/PIN change, delegated enrollers, revocation propagation, bounded-age policy, Bluetooth/cloud and old-#97 capability upgrade. Old profiles may Join without gaining missing capabilities.

## Authority and proof contract

Keep `companyFacts@2`, `_requireRecoverableFirstOwner`, recovery rotation lineage, existing assertions/operations/receipts and their signature domains valid. The authority checkpoint remains the pinned company/root/authority/facts/policy tuple. Adding B does **not** rewrite that checkpoint or A's existing Job. Local membership proof commitment is separate, protected and included in live session validation.

Define strict canonical `company.device.enroll@1` certificate bytes, signed by A's installation key under `wiredpart.company.device.enroll@1:`. Exact keys bind:

- proof kind and depth; parent kind `rootFacts@2` plus commitment; company/shop and stable authority checkpoint;
- typed `RootFactDeviceIssuer`: actual device ID, existing grant ID/version, installation/generation/key from the unchanged root-fact entry, per-issuer issuance sequence and preceding issuance commitment;
- recipient device/grant/version, installation/generation/key, the existing user ID and exact credential/permission versions, shop/capabilities;
- request UUID, random nonce and signed request commitment; `delegable=false` and depth **1**.

The initial issuer is that real root-fact device/version, not a fabricated legacy grant or synthetic enrollment certificate. The resolver verifies A's root-signed enrollment permission and signature, B's installation proof of possession, user-to-grant binding and componentwise scope attenuation. Effective rights intersect current root user rights, issuer device rights and child grant. Grant only `createJob` when that intersection allows it; never grant enrollment or infer authority from an administrator label. A valid public certificate alone cannot activate another installation. Reject unknown fields, unsupported proof kinds/depth, duplicate/conflicting grants, equivocation or mismatched causal predecessors; never pick a winner by wall-clock time.

Use `ResolvedCompanyMembership` and opaque `VerifiedJoinRequest` / `VerifiedJoinApproval` / `VerifiedJoinProvision` / `VerifiedPeerMembership` values with private constructors. Proposed kernel operations are `beginJoin`, `approveJoin`, `acceptJoinProvision`, `acknowledgeJoin` and `verifyPeerMembership`; callers cannot choose signing bytes/domain or obtain credential plaintext. The preapproval channel binds anonymous pairing transcript/direction/challenges and B's installation proof only. A's identity-bearing installation signature appears only in approved provision, completing the two-installation channel binding then; no caller-implemented encryptor receives a credential.

Owner assertions stay at their existing versions/domains. Rootless local assertions use an explicit new authorization version/domain and carry the signed member certificate, referencing the stable authority facts. Route them through the shared resolver and existing typed Create Job signing/admission path; retain the operation/receipt size limits and all actor, namespace, trust, floor, seal and before-commit rechecks. Do not pretend a member is present in the root fact's `devices` list.

Known revocation/floors for the user, child grant/device, issuer grant/device and authority deny admission. Advancing issuer sequence does not revoke earlier children. Protected issuer high-water state prevents rollback/forked issuance; it is distinct from admission floors. This increment rejects enrollment descendants beyond depth 1. A known newer recovery checkpoint invalidates old-epoch certificates; do not silently move B to new authority or replenish its credentials. Unseen offline changes remain unknowable under explicit `localContinuity`; `boundedAge` refuses. Existing authority packages remain authority-only checkpoints and do not acquire member credentials/history.

## Transport, credentials and lifetimes

Join uses encounter aliases in discovery, hello **and** pairing context, without persistent IDs, company names or counts. Purpose negotiation is transcript-bound and fails closed against old peers; legacy nearby-v2 copy retains its old bytes/behavior. In Join mode, refuse `sendTo`, `/v2/offer` and `/v2/transfer` before collection, offer metadata or UI display. Transport pairing never grants membership.

Reuse the existing X25519 agreement and one sequence owner. Add directional HKDF labels `wiredpart-v2/company-join@1/{guest,host}` and a bounded AES-256-GCM Join envelope, separate from `NearbyCodec`/`BackupPayload`. AAD binds purpose/version, transcript/session, direction, request, recipient key and issuance attempt. Every message has a unique random nonce. Current MAC-authenticated JSON is plaintext: it must contain only ciphertext and public routing/evidence, never salt/verifier material.

After rechecking live A/session/grants under the write lock and immediately before provisioning, the kernel encrypts A's **existing** credential salt/verifier/profile/version for exact B/company/user/grant. No raw PIN, root/recovery seed, verifier digest oracle or plaintext secret-returning issuer API. A public installation-signed issuance witness binds certificate/request, recipient, transcript, randomized ciphertext hash and attempt nonce. B validates all bindings before storing the credential in protected member custody. Its own attempt counter starts once; retry/restart never refills it. Reuse reservation-before-KDF and constant-time comparison. Budgets are per installation, not eight guesses globally.

Pairing retains its current five-minute window. `_paired()` cancels that timer today, so Join gets a separate five-minute monotonic approval/provisioning lease after Match. Sign-out, background/lock, stop, cancellation, expiry or transport replacement revokes the live approval/channel capability. B's preapproval request/channel stays entirely in memory: no protected reservation or SQL write while waiting for A. A crash before approval starts a new ephemeral request. Only an approved request that crossed its local durable boundary can resume under the same fixed request, through fresh pairing/key proof and live A approval; restart never resurrects channel keys or approval.

Bounds: one active Join per installation; 128 retained enrollment requests per issuer, with capacity refusal before mutation; certificate <=4 KiB; canonical authority-plus-lineage bundle <=32 KiB; credential payload <=1 KiB; total Join plaintext <=40 KiB and encoded HTTP body <=64 KiB. Refuse larger valid histories clearly rather than truncate proof or weaken current lineage validation. At most eight provisioning attempts per request, each bound to a fresh channel; no certificate/depth expansion through retries. Keep each existing/new protected record <=2,048 bytes and business operation/authorization <=65,536 bytes. Tests must measure maximum records; no capacity increase or SQLite plaintext fallback.

## Durable state, schema and recovery

Use additive schema **7**, with `company_membership_certificates` (immutable signed grants), `company_join_requests` (fixed approved request/grant identity and progress), and `company_join_events` (immutable public issuance/activation evidence and bounded recipient ciphertext). A persists issuance only after live authorized approval. B persists its activation intent only after complete approved-provision validation and explicit company consent; it writes no preapproval request. Exact admitted request/payload retry returns saved evidence; changed recipient/scope/actor/version refuses. One issuer sequence/certificate per request; one activation per recipient installation/generation. Never persist credential plaintext, PIN or ephemeral channel keys in SQL/logs.

| Stage | Durable meaning and continuation |
|---|---|
| `requesting` (memory only) | B's read-only fresh-store preflight and ephemeral request/channel await approval. Denial, invalid provision or absent consent leaves B's SQL and protected bytes/revisions unchanged. No durable resume is claimed here. |
| `approved` | A's current authority and request/grant/sequence are witnessed under protected CAS and SQL write lock. Approval alone cannot activate B. |
| `provisioned` | A has immutable certificate plus issuance/ciphertext evidence. Lost response may be retried on the same live channel; a fresh channel needs new proof/approval and bounded new issuance evidence for the **same grant**, not a new identity. |
| `activationPending` | B completely validated the approved provision and explicitly consented to its company/authority. Only now reserve protected activation intent and matching SQL evidence; no business authorization until local reconciliation completes. An orphan/divergent record fails closed. |
| `activated` | B's rootless protected binding, exact public proof, credential and SQL activation witness agree. A marks confirmed only after B's signed acknowledgment; a lost acknowledgment never causes B to reinstall credentials/reset attempts. |

These are local facts, not a cross-device atomic transaction. Refusal invariance compares the **rejecting installation** with its baseline immediately before that Join call, after normal app initialization. B rejecting a provision cannot roll back A's already approved issuance. Each admitted protected enrollment intent pins request, actor/versions, store/install generation and before/after SQL witness. Reconcile interrupted admitted local work before another Join/business command; never re-sign or repair tampered evidence. Pending state cannot sign business commands. Local business transactions remain isolated from enrollment writes, and A's Jobs/history are untouched.

Add a strict member custody profile with no root/recovery seed, no authority-package digest and explicit authority/membership/credential/install/store pins. Preserve old owner custody decoding/encoding outside authorized enrollment changes. A's compact issuer high-water/pending pins must fit protected capacity. B's recovery/reset UI directs it to an authorized owner; existing company restore/reset/legacy-write refusal remains in force.

Add all three tables to company marker scans, Create/Join empty-store preflights and backup/file guards; missing/corrupt schema-7 tables refuse. Update only existing exact schema/table mappings in native fixtures/restart proof readers; unknown schema 8 still refuses, old proof versions are never relabeled. Prove frozen schema-6 production database code refuses an actual schema-7 file without changing bytes, settings, Jobs or protected identity. Separately migrate an actual schema-6 store containing a committed Job and sealed protected pending command, generated through the frozen old production path. Additive schema 7 must preserve its historical intent/receipt/witness bytes and reconcile it, return the original receipt on exact retry, then permit another Job without duplication; family/record witnesses must not change encoding merely because tables were added. Rollback means retaining prior source/build/authority packages and stopping incompatible writes, never downgrading an enrolled store or copying A's database to B.

## Frozen disclosure boundary for review

"Public proof" means nonsecret signed evidence that may be stored/verified in SQL; it does **not** mean permission to broadcast or return it to an unknown network peer. Root facts, certificates, issuance witnesses and activation acknowledgments reveal company/shop/user/device/grant/installation identities. None contains a credential verifier or its digest. Discovery/hello/pairing reveal only encounter aliases and ephemeral handshake material. B's encrypted post-Match request proves its own unjoined installation/key/generation and request nonce to the selected approver; it contains no company/user identity or business metadata.

The first company-identity disclosure to unjoined B is A's recipient-bound encrypted provision, **after** explicit live owner approval of B's exact signed request/key/scope and final authority/permission rechecks. A discloses neither its identity-bearing authority proof nor installation signature before that approval; the channel's full two-installation binding is completed by this provision. This is the authorized enrollment exception, not permission conferred by Match. B verifies and pins A's authority/installation proof during activation; A already retains B's verified key/certificate. The PIN credential travels only inside that same protected recipient-bound provision, never in the public proof.

Fresh B has no prior company authority: SAS comparison and B's explicit consent to the displayed company/authority establish first trust. Wrong-company rejection means a mismatch with that approved enrollment binding or existing pinned trust; cryptography cannot correct a person approving the wrong company. Both installations retain the approved peer key **and** company/grant/proof binding durably, with protected commitments. Later verification resolves those retained bindings; it never accepts a caller-supplied replacement key. Retained-key proofs and LAN traffic can be linkable; encounter aliases do not promise anonymity.

Fresh A/B challenges after restart sign fresh nonces/transcript using those **already trusted** installation keys; they need not send identity-bearing certificates to an unknown peer. Unknown/untrusted peer challenges fail with a bounded generic refusal and no certificate, company IDs/names/counts or business content. Do not weaken this rule or invent an identity-hiding protocol here. Portable ancestry verification remains reusable, but introducing an unknown C proof over the network requires later trusted membership propagation. The third-identity test may verify and challenge a previously trusted legitimate C proof; it establishes no unknown-peer discovery/authentication, actual mesh or relay. This is an explicit limitation of the first Join, not a claim that encryption resolves mutual disclosure.
