# Issue 45 offline workflow scenarios, six areas

This is a planning inventory for [issue #45](https://github.com/xXKillerNoobYT/Weird-Parts-3rd-run/issues/45). The rows below are specifications, not passed tests. Every proof is **NOT_RUN**. They use the accepted product scope and feature candidate `95a06a96994ec03014a37075ce4406f183e3c12e`. The [foundation plan](foundation-plan.md) separates that draft candidate from merged source and records the current native gate.

Delivery stages are **F0** for the current native one-way and recovery gate, **F1** for company identity, users, and semantic core after issue #39, **F2** for Parts and Jobs usage migration followed by Notebook, and **R** for later warehouse, AI, Bluetooth, Internet, and partner features. A row's stage says when to consider delivery, not when its proof passed. Later feature ideas do not block issue #39 or the current foundation gate. An offline device reports only evidence it holds. It never claims current company-wide stock, shop receipt, or human acknowledgment from a nearby link alone.

Shared contracts used below are stable company, user, device, record, and operation IDs; signed author operations; separate carrier custody, semantic apply, shop receipt, and human acknowledgment; retry by operation ID and content hash; scoped authority; causal history; typed local views; bounded authenticated carry of unknown noncritical data; and fail-closed handling of unknown critical semantics. A carrier does not become an operation's author. No test fixture or shared record may contain a secret or PIN value. All scenarios assume local storage and device-to-device movement without a router or Internet unless a row explicitly discusses a later, approval-gated export.
